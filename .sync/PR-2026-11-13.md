## What changed in the port

- **68c0660 (perf, ported):** Added a per-stylesheet `declarationCache` keyed by the exact `style` string to the Rust counterparts of `lib/style.js` — `crates/g4/src/style.rs` (`compute_style`/`compute_own`) and `crates/g5/src/style.rs` (`compute_prop`). Repeated style computations now reuse parsed inline declarations instead of reparsing; keying by value means an updated `style` attribute can never return stale declarations. Includes Rust ports of the upstream `lib/style.test.js` test "caches inline declarations by style value" in both modules (same style string parses once; changing the string recomputes and grows the cache).
- **7dac404 (perf, no Rust port needed):** No code change. svgo-rs ports only the 34 `preset-default` plugins; `removeAttrs` is not one of them and has no Rust module, dispatch entry, or per-element pattern compilation to hoist, so there is no equivalent of the JS RegExp-recompilation cost to remove. The upstream change is a pure hoist with byte-identical output. The two added fixtures (`removeAttrs.08`, `removeAttrs.09`) are ported into `reference/svgo/test/plugins/`; the fixture harnesses only execute preset-default plugins, so they are stored with the reference without being executed, like the pre-existing `removeAttrs.01`–`07` fixtures.
- **7b0c686 (fix, ported):** `js2path` in `crates/g5/src/path.rs` no longer drops a moveto that is followed by another moveto — it only serializes. Consecutive movetos are already merged by `convertPathData`'s `collapseRepeated` stage when enabled, and now survive when it is disabled or the path has mid markers (each moveto is a marker vertex); a following relative moveto is no longer measured from the wrong point. `mergePaths` in `crates/g5/src/plugins.rs` now drops a trailing moveto of the previous path itself when the next path starts with an absolute moveto. Fixtures ported: `convertPathData.41`, `convertPathData.42`, `mergePaths.13`.
- **31194fb (fix, ported):** In the `convertToQ` degree-lowering step of `crates/g5/src/plugins/convert_path_data.rs`, a following `s` is now expanded with `longhand` from the original cubic data before `data` is replaced by the quadratic, so the `s` reflects the cubic's second control point instead of the quadratic's. Fixtures ported: new `convertPathData.43` (relative and absolute forms) and updated `convertPathData.16` expected output (`-5 0` → `-3 0`), which had encoded the buggy reflection.
- **Reference:** `reference/svgo` moved to `31194fb4b3b592d7a65956f8f3b343b9fd6b80a6` (verified byte-identical to the upstream tree) and `.svgo-sync` updated to the same sha.
