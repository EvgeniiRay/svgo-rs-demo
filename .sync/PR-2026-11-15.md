## What changed in the port

- **68c0660 (perf, behavior-preserving):** added a `declarationCache`
  keyed by the exact `style` string to the Rust ports of `lib/style.js`
  ([crates/g4/src/style.rs](crates/g4/src/style.rs),
  [crates/g5/src/style.rs](crates/g5/src/style.rs)), so repeated
  `compute_style`/`compute_prop` calls share one parse and attribute
  updates cannot return stale declarations. The upstream
  `lib/style.test.js` cache case is ported as Rust unit tests in both
  crates (same style on two rects → cache size 1; changed style →
  size 2, new value wins).
- **7dac404 (perf, reference-only):** no Rust change needed.
  `removeAttrs` is not part of preset-default and has no Rust port in
  this crate, so there is no per-element RegExp compilation to hoist.
  The JS change and its two new fixtures
  (`removeAttrs.08.svg.txt`, `removeAttrs.09.svg.txt`) are synced into
  `reference/svgo` for parity reference.
- **7b0c686 (fix):** `js2path` in
  [crates/g5/src/path.rs](crates/g5/src/path.rs) no longer drops a
  moveto followed by another moveto; it only serializes, leaving
  collapsing to `collapseRepeated`. `mergePaths` in
  [crates/g5/src/plugins.rs](crates/g5/src/plugins.rs) now drops a
  trailing moveto of the accumulated path when the next merged path
  starts with an absolute moveto. Fixtures `convertPathData.41`,
  `convertPathData.42` and `mergePaths.13` added.
- **31194fb (fix):** in
  [crates/g5/src/plugins/convert_path_data.rs](crates/g5/src/plugins/convert_path_data.rs),
  a following `s` is now expanded with the cubic's data before that
  data is replaced by the lowered quadratic, so the reflected control
  point is the cubic's second control point. Fixture
  `convertPathData.43` added; `convertPathData.16` updated to the
  corrected output.
- **Reference:** `reference/svgo` moved to `31194fb` (verified: no
  diff against upstream at that commit, excluding `node_modules`).
