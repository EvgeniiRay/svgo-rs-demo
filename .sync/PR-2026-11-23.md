## What changed

### svg/svgo@68c0660 — no port needed

Upstream caches css-tree-parsed inline style declarations per AST in
`lib/style.js` (a `WeakMap` keyed by the exact `style` string), removing a
reparse on every style computation. The Rust port has no equivalent cost:
each crate parses inline styles with a trivial split on `;` and `:`
(`crates/g5/src/style.rs`, `crates/g4/src/style.rs`, `crates/g2/src/css.rs`),
with no css-tree-style AST construction to cache. Upstream adds only a
`lib/style.test.js` unit test, which has no harness in this repo. Recorded as
an empty commit.

### svg/svgo@7dac404 — no port needed

Upstream hoists `RegExp` compilation in `plugins/removeAttrs.js` out of the
per-element visitor. `removeAttrs` is not part of SVGO `preset-default` and
was never ported to Rust (no crate implements it and `src/lib.rs` has no
dispatch for it), so there is no per-element compilation to hoist. The two
new fixtures (`removeAttrs.08.svg.txt`, `removeAttrs.09.svg.txt`) are ported
as data; the integrated harness (`tests/preset_fixtures.rs`) only runs
preset-default plugins, so they stay inert until a `removeAttrs` port exists.

### svg/svgo@7b0c686 — ported

- `js2path` in `crates/g5/src/path.rs` no longer drops a moveto that is followed by
  another moveto; it only serializes. Dropping one shifted every following
  relative command and removed a marker vertex. `convertPathData` already
  merges consecutive movetos in `collapseRepeated`, so the pairs that
  reached `js2path` were the ones kept on purpose (`collapseRepeated`
  disabled, or a mid marker present).
- `mergePaths` in `crates/g5/src/plugins.rs` now drops a trailing moveto of the
  accumulated path itself when the next merged path starts with an absolute
  moveto, which keeps `mergePaths.02` passing.
- Fixtures ported: `convertPathData.41`, `convertPathData.42`,
  `mergePaths.13`. All three failed before the change
  (`M0 0h10m5 5h1` instead of `M0 0h10m10 20m5 5h1`, etc.) and pass after.

### svg/svgo@31194fb — ported

- In the c→q degree lowering in
  `crates/g5/src/plugins/convert_path_data.rs`, a following `s` was expanded with
  `longhand()` after `data` had been replaced by the quadratic's
  `[qx, qy, x, y]`, so it reflected the quadratic control point instead of
  the cubic's second control point and changed the next curve's shape. The
  `s` is now expanded from the cubic data before `data` is replaced.
- Fixtures ported: `convertPathData.43` added (the issue's path in relative
  and absolute form), `convertPathData.16` expected output updated from the
  buggy `-5 0` to `-3 0`. Both failed before the change
  (`c6 0 6 3 6 6` instead of `c4 0 6 3 6 6`) and pass after.
